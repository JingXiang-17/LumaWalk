# LumaWalk ownership and change boundaries

This file describes repository areas, not access control. Keep shared API and product documentation synchronized when changing implementation behavior.

## Shared Documentation

* **`README.md`**: Project-wide setup and current implementation summary.
* **`docs/`**: Product requirements, team scope, project structure, and API contracts.
* **`backend/README.md`** and **`lunawalk_frontend/README.md`**: Component-level setup and usage instructions.

## Data Pipeline

* **Domain:** `data_pipeline/`
* **Scope:** OSM download, lighting patching, safe-haven scoring, and generated output artifacts.
* **Notes:** Coordinate changes to `data_pipeline/output/` with backend routing changes.

## Backend (Routing)

* **Domain:** `backend/main.py` and `backend/routing_service/`
* **Scope:** FastAPI application, CORS, graph loading, router registration, route algorithms, and route request/response models.

## Backend (Virtual Buddy)

* **Domain:** `backend/buddy_service/`
* **Scope:** Active sessions, telemetry, spatial deviation, and simulated alert dispatch.

## Frontend

* **Domain:** `lunawalk_frontend/`
* **Scope:** Flutter application, screens, state providers, API clients, assets, and platform targets.
* **Notes:** The old `frontend/` directory contains only a compatibility guide. New Flutter code belongs in `lunawalk_frontend/`.

## Contract Rule

When an endpoint or payload changes, update `docs/schemas.json`, the relevant component README, and the root README in the same change.

Current endpoint paths are:

* `/api/v1/route/`
* `/api/v1/buddy/session/start`
* `/api/v1/buddy/telemetry/ping`
